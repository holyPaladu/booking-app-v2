# 0005. Композиция модулей через service-порты + плоский канон файлов

- Статус: принято
- Дата: 2026-06-25

## Контекст
Внутри одного сервиса несколько модулей (`user`, `auth`, …), и им нужно использовать друг друга: `auth` при register/login обращается к `user` за поиском/созданием пользователя. Нужно правило, как модуль зависит от модуля, без жёсткой связности и без расхождения структуры (auth-модуль был на раскладке с подпапками `models/`/`types/`/`ports/`, user — на `*.repo.ts`/`entities/`; booking — на `v1.route.ts`/`types/`). Также копирование нового модуля руками порождало несогласованность.

## Решение
1. **Композиция через service-порты.** Каждый модуль публикует свою поверхность как `IXService` в `<name>.port.ts`. Другие модули зависят **только от этого интерфейса**, переданного в аргумент фабрики (`authService(users: IUserService)`), и **не** импортируют чужой `*.service.ts`/`*.repo.ts`/`sql`. Связывание — в composition root (`src/index.ts`). Циклы между модулями запрещены. Это продолжение DI через фабрики-замыкания и порты из [0004](0004-architecture-style-hybrid.md), распространённое на связь модуль↔модуль.
2. **Единый плоский канон файлов `<module>.<role>.ts`.** Каталог модуля плоский: `<name>.model.ts`, `<name>.entity.ts`, `<name>.port.ts`, `<name>.repo.ts`, `<name>.service.ts`, `<name>.route.ts`. Без подпапок `models/`/`types/`/`ports/`. Порт держит `IXRepo` (контракт SQL-слоя) и `IXService` (публичная поверхность).

Эталон — `services/auth/src/modules/user` (самодостаточный модуль) и `services/auth/src/modules/auth` (использует `user` через `IUserService`).

## Последствия
- (+) Явная, тестируемая связь модулей: в тестах подменяется `IXService` (см. `services/auth/test/auth.e2e.test.ts` — auth прогоняется с in-memory `IUserService`).
- (+) Одна раскладка для всех модулей.
- (−) Связывание модулей делается руками в `index.ts` (как и `deps`) — осознанный компромисс ради явности.
- (−) `services/booking/src/modules/bookings` пока на старой раскладке; миграция booking к канону — отдельной задачей.

## Обновление (2026-07): уточнение канона по читаемости
Решение в силе; уточнены детали раскладки (см. [conventions.md](../conventions.md)):
- **Модели входа переехали в `<name>.port.ts`** (отдельного `<name>.model.ts` больше нет): порт = полный контракт модуля (Elysia-модели + выводимые типы + интерфейсы), route импортирует `xModels` из порта. Убирает лишний файл и цикл route↔port.
- **Тонкие модули без логики** (`audit`, `session`, `login-attempt`) не дробятся на 4 файла — весь канон в одном `src/modules/<name>.ts`.
- **Composition root — `src/container.ts`** (bootstrap разнесён на `index.ts`/`app.ts`/`container.ts`/`workers.ts`), а не единый `src/index.ts`.
- **Именование:** TS-идентификаторы `camelCase`, `snake_case` только внутри SQL-строк; маппинг колонок — в repo.
