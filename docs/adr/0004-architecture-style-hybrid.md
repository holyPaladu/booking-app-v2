# 0004. Архитектурный стиль: гибрид

- Статус: принято
- Дата: 2026-06-24

## Контекст
Best practice Elysia предлагает строить модули на инстансах Elysia (контроллер/сервис/модель) с DI через `decorate`/`derive`. При этом хочется держать бизнес-логику переносимой и тестируемой вне фреймворка.

## Решение
Гибрид:
- **Ядро** (service, repo) — чистые фабрики-замыкания за портами, без зависимости от Elysia (совпадает с рекомендацией Elysia «non-request-dependent service = обычные функции»).
- **Край** (route, auth, валидация) — идиомы Elysia: `.model` + вывод типов из `static`, `@elysiajs/jwt`, `macro`/`guard` для request-зависимой auth, method chaining, prefix/group.
- DI зависимостей края (`response`, `cfg`) — через явный объект `deps` в фабрике роутов (сознательный отход от `.decorate` ради явности и портируемости).

## Последствия
- (+) Бизнес-логика тестируется без HTTP; HTTP-край остаётся идиоматичным для Elysia.
- (+) Чёткая граница «что зависит от Elysia, что нет».
- (−) Ручной `deps` вместо `.decorate` — чуть больше «прошивки» руками; осознанный компромисс.
